SwitchBot Lock Ultra — Control4 Driver

Version 1.2.0

Overview

Two-way integration between the SwitchBot Lock Ultra and Control4 through the SwitchBot Open Cloud API v1.1. The driver locks and unlocks the deadbolt, reports lock state, door state and battery level, and exposes events for Composer programming.

Like most cloud locks in Control4, this driver is the backend. The device the end user sees in Navigator is Control4's generic Door Lock driver, bound to this one.

Requirements

  • Control4 OS 3.3.0 or later
  • A SwitchBot Hub (Hub Mini, Hub 2 or later) paired to the lock, with Cloud Services enabled
  • A SwitchBot OpenToken and Secret Key
  • Controller with outbound HTTPS access to api.switch-bot.com
  • The lock must be controllable from the SwitchBot app, including remotely, before integrating

Obtaining the API credentials

  1. In the SwitchBot app: Profile → Preferences → About
  2. Tap App Version ten times to reveal Developer Options
  3. Copy the Token and the Secret Key

Installation

  1. In Composer Pro, System Design → Search, add SwitchBot Lock Ultra to the room.
  2. On the Properties tab, paste OpenToken and SecretKey.
  3. Actions → Test Connection. The Lua output reports success and the device count.
  4. Actions → Discover Devices, then choose the lock in Device Selection.
  5. Set Poll Frequency.
  6. Add My Drivers → Motorization → Door Lock to the same room. This is the device that appears in Navigator.
  7. Add a Door Contact sensor to the room for door state in the UI.

Programming events

EventFires when
Lock JammedThe motor reports jammed or blocked. Fires once, when the fault begins.
Calibration ErrorThe lock reports it is not calibrated. Fires once, when the fault begins.
Door Opened / Door ClosedDoor state changes. Not raised for the first reading after a restart.
Door Left OpenThe door has been open for five minutes.
Low BatteryBattery drops below 15%. Fires once per crossing.
Communication Failure / RestoredRepeated failures reaching the SwitchBot cloud, and recovery.
Do not treat the Door Lock tile as proof the door is secured. A relay is an output, so that tile reflects what Control4 commanded, not what the bolt did. For conditional logic that depends on the door genuinely being locked, use this driver's Lock Status property or the Lock State contact. Both come from polled device telemetry.

Notes

  • Polling, not webhooks. SwitchBot pushes events to a publicly reachable HTTPS URL, which a controller behind NAT cannot receive. The driver polls instead.
  • API limits. SwitchBot allows roughly 10,000 calls per day per account, shared by every application using it. One lock at 30-second polling uses about 2,880 calls per day; at 60 seconds, about 1,440. Each command adds one request plus a few verification reads.
  • Commands are verified. The cloud accepting a command is not treated as proof the bolt moved; the driver re-reads the real state before updating the UI.
  • No user codes or lock history. Lock, unlock and telemetry only.
